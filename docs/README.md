## 🎯 Documentation Principles

### Keep It Updated
When you make architectural decisions or add features:
1. Update relevant documentation
2. Add code examples if helpful
3. Note any breaking changes

### Keep It Simple
- Write for developers (including future you)
- Use clear language
- Include code examples
- Explain the "why" not just the "what"

### Keep It Organized
- All docs in `/docs/` folder
- README.md at project root points here
- Use clear file names
- Group related docs

## 🔄 Documentation Workflow

1. **Before coding:** Review relevant docs
2. **While coding:** Reference code snippets
3. **After feature:** Update implementation summary
4. **After changes:** Update master plan if needed

## 📝 Contributing to Docs

When adding new documentation:
- Place in `/docs/` folder
- Add link to this README
- Use markdown formatting
- Include examples where helpful
- Keep formatting consistent
